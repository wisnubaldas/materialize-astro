## Ringkasan Perubahan

- Memperbaiki normalisasi permission deploy untuk generator laporan mingguan.
- Menambahkan pengaturan permission untuk folder output `docs/report-mingguan` pada deploy development dan production.
- Root cause: pipeline GitLab menjalankan deploy via SSH sebagai `root`, sehingga file/folder tracked hasil `git reset --hard` dapat menjadi milik `root`. Sebelumnya script hanya membetulkan permission `docs/weekly-report-generator`, padahal output laporan ditulis ke `docs/report-mingguan`.

- `deploy-production.sh`

## Hasil Verifikasi

  - membuat folder `docs/report-mingguan` jika belum ada;
  - mengubah ownership ke `wisnu:wisnu`;
  - memberi permission direktori `775`;
  - memberi permission file Markdown existing `664`.
- `bash -n deploy-development.sh; bash -n deploy-production.sh` belum bisa dijalankan lokal karena environment Windows mengarah ke WSL tanpa distro terpasang.

## Gap / Risiko

- Perlu deploy ulang di server staging agar permission folder output dibetulkan oleh script terbaru.
- Jika cronjob dijalankan oleh user selain `wisnu`, variabel `DEPLOY_USER` dan `DEPLOY_GROUP` perlu disesuaikan dengan user cron aktual.
