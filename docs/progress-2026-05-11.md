- Menjalankan Phase 1 quick wins refactor backend:
  - memperbaiki Ruff `B012` pada middleware request logging (menghilangkan `return` di blok `finally`);
  - menghapus `print()` runtime pada `main.py`, `buildup_service.py`, dan SSE stream handler;
  - memperbaiki pola raise exception (`B904`) dengan `raise ... from ...` pada SSE dan proses generate PDF build up.
- Menuntaskan sisa warning Ruff hingga `0` temuan:
  - refactor `ceisa_log_repository` dengan object payload/metrik untuk menghilangkan warning `too-many-arguments`;
  - refactor `warehouse_repositrory.get_masterwaybill_by_awbs` ke helper methods untuk menurunkan kompleksitas cabang (`too-many-branches`);
  - refactor `warehouse_service.generate_ffm_preview` + context object untuk menghilangkan `too-many-branches` dan `too-many-arguments`;
  - normalisasi schema CEISA X-Ray ke `snake_case` internal + alias camelCase agar lolos rule naming (`N815`) tanpa mengubah kontrak payload eksternal.
- Penyesuaian format header FWB generator di frontend EDI: segmen volume `MC` digabung ke quantity/weight (contoh `T1K12MC10.45`), tidak lagi dipisah dengan `/`.
- Perbaikan formatter segmen `RTG` di FWB generator agar sesuai grammar Cargo-IMP:
  - token routing pertama otomatis dipastikan mengandung carrier code (contoh input `CGK/DPS` menjadi `RTG/CGKII/DPS`);
  - mendukung input user-friendly (dipisah slash/spasi/koma) dan fallback aman ke `RTG/{destination}II`.
- Perbaikan formatter segmen `CVD` di FWB generator:
  - menambahkan normalisasi indikator prepaid/collect (`weight_charge_pp_cc`) agar hanya menghasilkan kode valid (`PP`, `CC`, `PC`, `CP`);
  - input tidak valid seperti `0` otomatis fallback ke `PP` untuk mencegah parser error pada `DE403_PCInd`.
- Penyesuaian formatter party segment (`SHP/CNE`) di FWB generator agar postal code mengikuti pola coded location Cargo-IMP:
  - postal digabung pada baris country (`/{COUNTRY}/{POSTAL}`), bukan segmen terpisah `ZIP/...`;
  - contoh: `/ID/1435` menggantikan kombinasi `/ID` lalu `ZIP/1435`.
- Hardening validasi FWB untuk lolos parse2 pada kondisi data form tidak lengkap:
  - normalisasi airport code (`origin/destination`) ke 3 alpha dengan fallback aman;
  - normalisasi country code ke 2 alpha, city/place dipotong ke panjang aman, dan postal code dibersihkan ke alfanumerik;
  - segmen `SHP/CNE` dipastikan selalu membentuk blok wajib (`NAM`, `ADR`, `LOC`, country line), termasuk fallback nilai default;
  - merge `buildFwbDefaults` + data `fwb` saat render form dan saat submit, agar field penting otomatis terisi saat proses validasi/generate pesan.
- Memperbarui pedoman backend agent pada `materialize-fastapi/backend_agent.md` dengan aturan wajib performa berbasis Ruff.
- Menambahkan aturan wajib async safety: larangan mencampur `async def` dengan kode blocking (contoh `time.sleep()`), serta panduan penggunaan `await asyncio.sleep(...)` dan threadpool untuk library blocking.
- Menambahkan query baru untuk pencarian MAWB domestic outgoing saat proses create build up.
- Mengubah alur lookup MAWB di repository warehouse agar:
  - query export tetap dijalankan lebih dulu;
  - query domestic outgoing dijalankan untuk MAWB yang belum ditemukan;
  - hasil akhir tetap digabung tanpa duplikasi dan mengikuti urutan input MAWB.
- Memperbarui ringkasan endpoint warehouse masterwaybill bulk agar mencerminkan sumber data export + domestic outgoing.
- Rename template PDF build up dari `air_cargo_manifest2.html` menjadi `pdf_build_up.html` dan update referensi di service.
- Perbaikan layout kolom tabel PDF manifest (`ULD / NUMBER MAWB`, `WEIGHT`, `NUMBER OF PIECES`) agar teks tidak terpotong dan kolom lebih proporsional.
- Menjalankan Phase 2 refactor backend untuk modul `auth` dan `setting`:
  - route/controller dirapikan agar fokus pada endpoint definition + dependency injection + pemanggilan service;
  - query database dan validasi bisnis dipindahkan ke layer `repository` dan `service` baru;
  - menambah dependency factory khusus read/write untuk `SettingService` dan dependency service untuk `AuthService`.
- Menjalankan Phase 3 standardisasi response error backend:
